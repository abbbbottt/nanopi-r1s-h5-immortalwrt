1 · 硬件真相：你的 WiFi 芯片是什么

绝大多数 NanoPi 教程都在讲 NanoPi R1 / R2S，而 R1S 这一代换了料。先把事实钉死：

WiFi 芯片
Realtek RTL8189ETV
SDIO 接口，挂在 mmc1 上
驱动形态
树外驱动
kmod-rtl8189es，上游内核不含
规格
2.4GHz b/g/n · 1x1
IPX/U.FL 外置天线口，无蓝牙
容易踩的坑
NanoPi R1（H3 那台）用的是博通 AP6212，靠主线的 brcmfmac 驱动，开箱可用。 但 R1S 系列换成了 Realtek RTL8189ETV，主线内核里没有它的驱动。 如果你按 R1 的教程去编，刷完会发现「无线」菜单里空空如也——不是硬件坏，是驱动没编进去。

好消息是，两边都对得上：

  • ImmortalWrt 源码树里有一个专门的包 package/kernel/rtl8189es，输出的就是 kmod-rtl8189es；
  • 官方 25.12.2 的 sunxi/cortexa53 内核模块源里能查到 kmod-rtl8189es 6.12.103.2025.09.27~0a5d0411-r1（2025-09-27 的驱动快照，比你手上固件新得多）；
  • 主线内核的设备树里 &mmc1 已经带 wifi_pwrseq 供电时序和 rtl8189etv: wifi@1 子节点， 硬件描述是现成的，不需要自己打补丁。

3 · 方案：GitHub Actions 云端编译

编译 OpenWrt 需要 Linux（Cygwin 不行，因为文件系统大小写不敏感）。你在 Windows 上， 与其装 WSL2 或 Docker Desktop、再等两小时本地烧 CPU，不如直接让 GitHub 的机器替你编—— 免费额度完全够用，跑完直接把固件下载下来。

  1. 把编译套件推到你自己的 GitHub 仓库 新建一个仓库，把本指南交付的整个目录推上去（含 .github/workflows/build.yml）。 或者直接 Fork 一个现成的 Actions 模板仓库，再把本目录的文件覆盖进去。
  2. 打开 Actions 的写权限 仓库 Settings → Actions → General → Workflow permissions， 选 Read and write permissions。不开这个，最后发布 Release 会 403。
  3. 手动触发一次 进 Actions 标签页，左侧选 Build ImmortalWrt (NanoPi R1S H5)， 点 Run workflow。以后每周一北京时间 04:00 也会自动跑一次。
  4. 等编译完成（约 1~2 小时） 工作流会先清盘、装依赖、拉源码、更新 feeds、注入自定义文件， 然后强制校验两项关键配置：设备是否选中、kmod-rtl8189es 是否编入。 任何一项没生效就直接报错中止——这就是「不会漏掉 WiFi 驱动」的保险。
  5. 下载产物 在该次运行的 Artifacts 里下载，同时会自动发一个 Release，方便长期保存。

产物文件名：

immortalwrt-25.12.2-sunxi-cortexa53-friendlyarm_nanopi-r1s-h5-ext4-sdcard.img.gz
immortalwrt-25.12.2-sunxi-cortexa53-friendlyarm_nanopi-r1s-h5-squashfs-sdcard.img.gz
profiles.json / sha256sums / config.seed / build.log
ext4 还是 squashfs？
ext4：单一可读写分区，和你原来那版结构一致，跑 Docker、装大体积包更舒服。
squashfs：只读根 + 可写 overlay，改崩了可以一键恢复出厂，网页升级也更省心。 两个都编出来了，随意挑，建议日常用 squashfs。

4 · 交付物：目录结构与文件

nanopi-r1s-h5-immortalwrt/ ├── .github/workflows/build.yml 云端编译工作流（清盘 / 依赖 / feeds / 校验 / 发布） ├── configs/nanopi-r1s-h5.config 编译配置片段（追加到 .config 再 defconfig） ├── diy-part1.sh feeds 更新前执行（默认空操作，留扩展位） ├── diy-part2.sh 把 files/ 注入源码树并补执行位 ├── files/ 直接进固件的文件覆盖层 │ └── etc/ │ ├── init.d/nanopi-wifi S99 初始化无线监管域 / SSID（默认不开射频） │ └── uci-defaults/99-nanopi-init 主机名 / 时区 / NTP / 启用上面的服务 └── README.md 同内容速查版

几个设计上的取舍，值得说明

  • 配置写成「片段」而不是完整 .config。 因为 make defconfig 会自动补齐默认值；写错的选项会被静默忽略，不会让编译失败。 比塞一份几百 KB 的完整 .config 健壮得多，也方便你一眼看懂改了什么。
  • WiFi 初始化放在 /etc/init.d/ 而不是 /etc/uci-defaults/。 首次开机时 /etc/config/wireless 是网络服务在 uci-defaults 之后才生成的。 放在 START=99（晚于 S40network）才拿得到 radio0 段，否则脚本会空跑。 脚本自带幂等标记，只生效一次。
  • 默认不开射频。 见下一节的已知风险——这颗芯片的树外驱动有崩过机的历史， 先让你手动确认一次更稳妥。想开机自动开，把脚本里那一行注释去掉即可。

6 · 刷机与开启 WiFi

刷机

  1. 解压 .img.gz 得到 .img。必须先解压，别拿 .gz 直接刷。
  2. 用 Rufus（Windows）或 balenaEtcher 把 .img 写入 TF 卡。
  3. 卡插回板子，上电。默认地址 http://192.168.1.1，用户名 root，密码为空。
  4. 网口映射：eth0 = WAN，eth1 = LAN（板载千兆口是 eth0 走的 RTL8211E，USB 转的那口是另一路）。
从你现有的老固件升级？
因为你原来那版（ext4-sdcard）也是同一个 target，但跨了大版本、内核和分区表都变了， 建议整卡重刷，不要用网页升级。等你已经在跑本项目的固件之后， 以后 LuCI → 系统 → 备份/升级固件，直接上传新的 *-sdcard.img.gz（不用解压）并勾选保留配置，就能热升级。

开启 WiFi

固件默认不自动开射频。两种开法：

网页（推荐）：LuCI → 网络 → 无线 → 点 radio0 的「启用」→ 改 SSID / 加密方式 / 密码 → 保存并应用。

命令行：

# 打开射频并配一个 WPA2 热点
uci set wireless.radio0.disabled='0'
uci set wireless.radio0.country='CN'
uci set wireless.radio0.channel='6'
uci set wireless.default_radio0.ssid='MyWiFi'
uci set wireless.default_radio0.encryption='psk2'
uci set wireless.default_radio0.key='换成你的密码'
uci commit wireless
wifi reload

验证是否真的起来了：

# 1. 驱动有没有正常加载（应该看到 rtl8189es 的版权行和 mmc1 上的 SDIO 设备）
dmesg | grep -iE 'rtl8189|8189es|mmc1'

# 2. 无线接口是否存在
iw dev
ip link show wlan0

# 3. 射频状态（disabled 应变成 no）
iwinfo
uci show wireless | grep disabled

# 4. 拿它当客户端连上级 WiFi
uci set wireless.radio0.disabled='0'
uci set wireless.sta=wifi-iface
uci set wireless.sta.device='radio0'
uci set wireless.sta.mode='sta'
uci set wireless.sta.network='wan'
uci set wireless.sta.ssid='上级WiFi名'
uci set wireless.sta.key='上级WiFi密码'
uci commit wireless && wifi reload

7 · 使用 USB 的 4G / 5G 上网设备

插在 USB 口上的「5G 移动 WiFi」有好几种技术形态，驱动完全不同。官方 25.12.2 镜像 一个都不带，所以本项目把它们全部编进了固件，一张表覆盖你所有可能遇到的设备：

设备形态内核驱动拨号方式
手机 USB 共享、多数随身 WiFi kmod-usb-net-rndis 自动出现网卡，当普通以太网口用 DHCP
部分上网卡的 ECM 模式 kmod-usb-net-cdc-ether 同上
新式随身 WiFi、华为设备 kmod-usb-net-cdc-ncm
kmod-usb-net-huawei-cdc-ncm		 LuCI 建「NCM」协议接口
高通 5G 模块（RM500Q、MH5000 等） kmod-usb-net-qmi-wwan uqmi，LuCI 选「QMI」协议
模块的 MBIM 模式 kmod-usb-net-cdc-mbim umbim，LuCI 选「MBIM」协议
AT 指令口（查信号 / 发短信 / 解 PIN） kmod-usb-serial-option + comgt picocom / sms-tool
为什么不能刷完再装驱动？
内核模块（kmod-*）的依赖里写死了内核的配置哈希。本固件编出来的内核是 6.12.103~dbdb90a7…，而官方源里的模块是按 b78b4d5e… 编的， 哈希不一致，apk 会直接拒绝安装。所以「刷完再 apk add 一个驱动」这条路是堵死的， 必须像本项目这样编进固件——这也是为什么第 5 节的包清单里要一次放这么多。

插上后先确认设备识别情况

# 1. 内核有没有认到这个 USB 设备
dmesg | tail -30

# 2. 设备绑到了哪个驱动（rndis_host / cdc_ether / qmi_wwan / option）
lsusb -t

# 3. RNDIS / ECM 网卡会直接出现在这里（usb0 / eth2 之类）
ip link

# 4. QMI / MBIM 模块的控制口与 AT 口
ls -l /dev/cdc-wdm* /dev/ttyUSB*

情况 A：ip link 里多出了 usb0（RNDIS / ECM）

最省事，当普通以太网口用，直接跑 DHCP：

uci set network.wwan=interface
uci set network.wwan.proto='dhcp'
uci set network.wwan.device='usb0'
uci set network.wwan.metric='20'
uci commit network
/etc/init.d/network reload
ip addr show usb0

情况 B：高通模块（QMI / MBIM）

# 先确认模块已切成 QMI 模式（能打印厂商信息就说明通了）
qmicli -d /dev/cdc-wdm0 --dms-get-manufacturer
qmicli -d /dev/cdc-wdm0 --dms-get-model

# MBIM 模式则用：
mbimcli -d /dev/cdc-wdm0 --query-device-caps

# 然后在 LuCI → 网络 → 接口 → 新建，
# 协议选「QMI Cellular」或「MBIM Cellular」，填运营商 APN 即可

排障表

现象原因处理
lsusb 里显示成光驱 / 存储设备 上网卡默认停在 CD-ROM 模式 固件已内置 usb-modeswitch，会自动切换；没切成功就重新插拔或重启
驱动都认到了但拨不上号 APN 填错 查运营商 APN（移动 cmnet、联通 3gnet、电信 ctnet）
dmesg 里完全没有插入记录 供电不足 R1S H5 的 USB 口带不动大功率 5G 模块，必须用带外接供电的 USB Hub
识别成 ttyUSB* 但没有网络口 模块处于「仅 AT / 纯串口」模式 picocom -b 115200 /dev/ttyUSB2 进去发 AT 指令切模式（如 AT+QCFG="usbnet",1 切 ECM、=2 切 MBIM、=0 切 QMI/RMNET）
信号弱 / 只有 4G 频段或天线问题 用 LuCI 里新增的「3G/4G 信息」「ModemBand」页面看信号强度与频段，必要时手动锁频
一个兜底手段
固件里还带了 ModemManager（默认不启动）。如果你的模块用 QMI、MBIM 都拨不上， 可以手动启用它来接管——它对各种冷门模块的自动识别更聪明： /etc/init.d/modemmanager enable && /etc/init.d/modemmanager start， 然后用 mmcli -L 看识别结果。注意启用后它会占用 AT 口，别再同时用手动拨号。

8 · 已知风险与排障

最大的不确定性：AP 模式下可能 kernel panic
RTL8189ES 是树外驱动，长期有社区反馈它在较新内核上开 AP 会导致内核崩溃、重启循环。 已知的具体案例是某项目在 内核 5.15 上，该驱动开 AP 会 panic， 所以他们干脆把 AP 默认关掉，只保留客户端模式。

本方案用的是 内核 6.12 + 2025-09-27 的驱动快照，比那些报告里的版本新不少， 有可能已经修好，但不能保证——最终得你自己实机验证。所以固件默认不开射频， 就是给你留一次「手动确认」的机会。
现象可能原因处理
LuCI 里根本没有「无线」菜单 要么 kmod-rtl8189es 没编进去，要么没装 wpad 跑 opkg list-installed | grep -E 'rtl8189|wpad'（25.12 是 apk list）确认；缺了就补装或重编
iw dev 里没有 wlan0 驱动没绑定到 SDIO 设备 / 固件加载失败 dmesg | grep -i mmc1 看有没有探测到设备；lsmod | grep 8189；必要时 modprobe rtl8189es
开 AP 后立刻重启 / 死机 驱动 bug（见上方红框） ① 先用 STA 模式；② 退回 v23.05.x；③ 换 USB 无线网卡；④ 只走有线
能连上但没网 防火墙 zone 没把 wlan0 划进 lan LuCI → 网络 → 防火墙，把 wlan0 所属接口加进 lan zone，允许转发到 wan
TF 卡空间不够 / 装不了 Docker sunxi 这个 target 不会在首次启动时自动扩容根分区，卡上可用空间就等于编译时设的 CONFIG_TARGET_ROOTFS_PARTSIZE（当前 1024MB） ① 用内置的 DiskMan 把第二分区扩到整张卡再 resize2fs（推荐，一次搞定）；② 或把该值调更大重编
编译到最后报 ext4_allocate_best_fit_partial: failed to allocate ... out of space? 根文件系统分区太小，装不下所选的全部软件包（第一次就踩到这个坑：512MB 差 175 个块） 把 configs/*.config 里的 CONFIG_TARGET_ROOTFS_PARTSIZE 调大（现在 1024）后重跑
编译在 make download 阶段挂掉 个别源码包下载超时 重跑一次工作流即可；GitHub 上偶发，非配置问题

如果想自己看编译日志

每次构建的 build.log 会一起打包进产物里。失败时先看日志末尾， 再配合「并行失败时单线程重试」那一步的输出定位——单线程重试会给出完整的出错现场。

9 · 备选方案

A · 本地 Docker 编译

想完全掌控、离线反复编，就在 WSL2 或 Docker Desktop 里跑：

docker run -it --name iwrt \
  -v "$PWD:/work" -w /work \
  ubuntu:22.04 bash

# 容器内
apt update && apt install -y sudo git
sudo bash -c 'bash <(curl -s \
  https://build-scripts.immortalwrt.org/init_build_environment.sh)'
git clone -b v25.12.2 --single-branch \
  --filter=blob:none \
  https://github.com/immortalwrt/immortalwrt openwrt
cd openwrt && ./scripts/feeds update -a \
  && ./scripts/feeds install -a
cat ../configs/nanopi-r1s-h5.config >> .config
make defconfig
make download -j8
make -j$(nproc) V=s

需要约 25GB 磁盘、8GB 内存起步，首次全量编译 1~2 小时。 路径里不能有空格和非 ASCII 字符。

B · 不编译：官方镜像 + 装驱动

其实官方已经出了这台机器的镜像和驱动包，两步就能用：

# 1. 下载官方 25.12.2 镜像并刷入
#    https://downloads.immortalwrt.org
#    /releases/25.12.2/targets/sunxi/
#    cortexa53/

# 2. 开机后装 WiFi 驱动（25.12 用 apk）
apk update
apk add kmod-rtl8189es
apk add wpad-basic-mbedtls iw iwinfo

# 2b. 需要 USB 4G/5G 上网设备就再加这一串
apk add kmod-usb-net-rndis kmod-usb-net-cdc-ether kmod-usb-net-cdc-ncm \
        kmod-usb-net-cdc-mbim kmod-usb-net-qmi-wwan kmod-usb-serial-option \
        kmod-usb-serial-wwan kmod-usb-acm kmod-usb-wdm kmod-wwan \
        usb-modeswitch uqmi umbim comgt picocom \
        luci-proto-qmi luci-proto-mbim luci-proto-ncm

# 3. 开射频
uci set wireless.radio0.disabled='0'
uci commit wireless && wifi reload

优点：十分钟搞定。缺点：固件是官方原味（英文界面、包很少）， 想内置插件和中文界面还是得自己编。
关键前提：只有刷官方镜像时这套 apk add 才成立——官方镜像的内核哈希 与官方模块源完全一致。刷本项目编出来的固件则装不上官方 kmod-* （哈希是 dbdb90a7…，对不上官方源的 b78b4d5e…）， 那种情况下驱动必须编进固件。
